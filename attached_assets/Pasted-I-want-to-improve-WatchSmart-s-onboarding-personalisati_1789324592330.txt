--------------------------------------------------
1. MAKE ONBOARDING CARDS USE SELECTED GENRES
--------------------------------------------------

The current taste cards can feel random and sometimes show titles that do not make sense for the genres the user has just selected.

Fix this.

The genres selected immediately before the taste-card stage must materially influence which onboarding titles are shown.

For example:

If a user chooses:
Crime
Thriller
Mystery

their onboarding cards should primarily contain recognisable, good-quality titles relevant to Crime / Thriller / Mystery.

They should NOT receive a generic set of onboarding titles that every user receives.

Do not simply require an exact genre match on every card.

Use approximately this principle:

~80% = strongly relevant to one or more selected genres
~20% = controlled adjacent/discovery titles

The purpose of the 20% is to learn whether the user has related interests that they did not explicitly select.

Do not make this a hard-coded percentage if the current architecture has a cleaner way to achieve the same behaviour.

--------------------------------------------------
2. QUALITY OF ONBOARDING TITLES
--------------------------------------------------

Onboarding is the user's first experience of WatchSmart.

Prioritise titles that are:

- recognisable
- reasonably popular
- good quality
- representative of the genres selected
- diverse within those genres
- appropriate for WatchSmart's existing catalogue rules

Avoid obscure/niche titles unless they are genuinely useful for determining taste.

Avoid filling onboarding with several extremely similar titles.

Example:

Crime + Thriller + Mystery should not simply produce 10 generic crime films.

Try to expose different areas such as:

- psychological thriller
- detective/investigation
- mystery
- dark crime
- action thriller
- character-driven crime
- suspense

This gives WatchSmart better information about what specifically the user likes.

--------------------------------------------------
3. REDUCE NUMBER OF TASTE CARDS
--------------------------------------------------

Reduce the taste-card onboarding stage.

Target:

Maximum: 10 cards.

After the user has interacted with 5 cards, allow them to finish the taste stage early if they want.

The experience should therefore be:

5 interactions minimum
→ user can continue/finish early

OR

continue up to a maximum of 10 cards for stronger personalisation.

Make the early-finish option clear but not intrusive.

Do not force users through a long sequence.

--------------------------------------------------
4. STRONG ONBOARDING WEIGHT
--------------------------------------------------

This is extremely important.

Interactions during taste onboarding should have STRONG initial influence on the user's recommendation profile.

These are explicit taste-training interactions.

They should not have the same weight as:

- an impression
- simply seeing a card
- weak passive behaviour

A card merely being displayed must have ZERO taste influence.

Only deliberate user interactions should train the profile.

Inspect the existing onboarding interaction options and recommendation architecture before changing weighting.

Positive onboarding responses should create strong positive affinities.

Negative onboarding responses should create meaningful negative affinities.

If different levels such as Loved / Liked / Okay / Didn't Like are available during this process, preserve the difference in strength between them.

Do NOT allow one individual movie/show to completely dominate the profile.

Combine evidence across all onboarding interactions.

--------------------------------------------------
5. LEARN MORE THAN GENRE
--------------------------------------------------

Do not reduce onboarding learning to:

"User liked Thriller → Thriller +1"

Use the existing metadata and recommendation architecture to learn as much reliable information as WatchSmart already supports.

Where available, onboarding interactions should influence:

- genres
- subgenres
- themes
- tone/mood
- cast
- director
- writer/creator
- keywords
- language
- release era
- similar-title relationships

Do not invent metadata that WatchSmart does not actually have.

Use the existing affinity/scoring system wherever possible rather than building a second recommendation engine.

--------------------------------------------------
6. STRONG AT FIRST, THEN DECAY
--------------------------------------------------

Onboarding should be especially influential for a brand-new user because WatchSmart has little other evidence.

However, onboarding should NOT permanently control recommendations.

Use a gradual weighting/decay approach.

Conceptually:

0–20 genuine post-onboarding interactions:
Onboarding is one of the strongest personalisation signals.

20–50:
Onboarding and real behaviour both matter significantly.

50–100:
Actual behaviour should increasingly dominate.

100+:
Onboarding remains historical preference evidence, but current behaviour should be substantially more important.

Do not blindly hard-code these exact ranges if the current recommendation architecture supports a better confidence/decay model.

The objective is:

Strong initial personalisation
→ increasingly behaviour-driven personalisation.

Explain exactly how you implement this.
