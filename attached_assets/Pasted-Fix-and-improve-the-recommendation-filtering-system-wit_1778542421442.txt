Fix and improve the recommendation/filtering system without redesigning the UI.

CORE FILTERING RULES
- Treat Family/Kids as audience classifications, not normal genres.
- If Family/Kids is disabled, exclude any title with:
  - Family genre
  - Kids genre/category
  - audience_type = kids or family
  - children/family certifications
  - animation + family/comedy/adventure signals
- This exclusion must happen BEFORE genre matching/ranking.
- Comedy + Family must not appear in adult Comedy.
- Action + Family must not appear in adult Action.
- Adventure + Kids must not appear in adult Adventure.

ANIME / BOLLYWOOD FILTERING
- Keep Anime and Bollywood disabled by default.
- Only allow them if user explicitly enables them.
- Anime filtering should detect:
  - anime genres
  - anime studios/tags
  - Japanese animation metadata/signals
- Bollywood filtering should detect:
  - Indian cinema tags
  - Hindi/Telugu/Tamil metadata
  - Bollywood production signals

SUBSCRIPTION FILTERING
- User subscription filters must work correctly.
- Only show titles available on selected services when provider data exists.
- If provider data is unknown, handle safely without collapsing the pool.
- Support provider tiers later, but keep current system stable first.

NO REPEATS / MEMORY SYSTEM
- Track every movie shown to the user, not just watched/saved/skipped.
- Store shown_at timestamps per user/movie.
- Never show the same movie twice in the same session.
- Saved, watched, skipped, disliked, and recently shown titles must not reappear.
- Exclude duplicates across all tabs.
- If the pool becomes low, only reintroduce old movies after a cooldown period.
- Increase cooldown if user repeatedly skips the same movie.

PERSONALIZATION LEARNING
- Learn from:
  - saves
  - watched
  - skips
  - detail-page opens
  - trailer opens
  - watchlist behavior
- Increase/decrease genre affinity scores over time.
- Use weighted ranking, not hard genre loops.
- Keep recommendations varied while still personal.
- Prevent echo chambers and repetitive genre recycling.

DAILY USER POOL REFRESH
- Refresh each user’s Discover pool daily.
- Use:
  - latest catalog imports
  - subscriptions
  - hard filters
  - watched/saved/skipped exclusions
  - recently shown exclusions
  - learned preferences
- Store last_pool_refresh_at per user.
- Add fresh titles daily without resetting user history.

GLOBAL MOVIE CATALOG
- Keep importing movies daily from TMDB.
- Use multiple endpoints and pagination.
- Deduplicate by tmdb_id.
- Convert poster_path to full poster_url.
- Exclude movies with no posters from Discover.
- Maintain a very large rotating pool.

DEBUG / VALIDATION
Add debug stats for:
- total catalog size
- pool size after filters
- after family/anime/Bollywood exclusions
- after watched/saved/skipped exclusions
- after recently shown exclusions
- final Discover pool size
- top learned genres
- number of new titles added daily

GOAL
The app should feel highly personal, intelligent, strict with deal-breaker filters, varied enough to avoid repetition, and refreshed daily per user without recycling the same titles.

Current problem:

Requirements:

ONBOARDING GENRE SELECTION

FIRST 18 SWIPE TRAINING

- genres

- audience type

- runtime

STRICT FILTERS

FIRST DISCOVER EXPERIENCE
- After onboarding, Discover should feel noticeably personalized.
- The first feed should clearly reflect onboarding behavior.
- Avoid generic/random recommendations after setup.

PERSISTENCE

- Do not lose onboarding preference data after refresh/relogin.

DEBUGGING
Add debug stats/logging for:
- onboarding genres selected
- onboarding swipe actions

GOAL
