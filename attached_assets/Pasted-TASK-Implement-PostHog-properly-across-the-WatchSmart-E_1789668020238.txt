WatchSmart is already a functioning application and is currently being tested through TestFlight.

Do NOT redesign screens.
Do NOT change recommendation behaviour.
Do NOT change existing API behaviour.
Do NOT change authentication behaviour.
Do NOT upgrade Expo/React Native unless absolutely required.
Do NOT add unnecessary native dependencies.
Do NOT expose secrets in source control.

Before changing anything, audit the current project and determine:

1. Expo SDK/version

3. Existing analytics packages
4. Existing error/crash tracking
5. Existing environment-variable/secrets system
6. Authentication/user ID implementation

Report this audit first.

==================================================
1. POSTHOG CORE SETUP
==================================================

Install the current supported PostHog SDK appropriate for this Expo React Native project.

Use the EU PostHog host because this project is using eu.posthog.com.

Store configuration through the project's existing environment/secrets system.

Expected variables should be similar to:

EXPO_PUBLIC_POSTHOG_KEY
EXPO_PUBLIC_POSTHOG_HOST

Do NOT hardcode configuration throughout the application.

The PostHog project token/public ingestion key may be used client-side where this is the normal supported PostHog implementation, but do not expose private/admin/personal API keys.

Create ONE central analytics module/service.

For example:

src/services/analytics.ts

or follow the project's existing architecture.

Components/screens should call the analytics service rather than importing and configuring PostHog independently.


==================================================
2. USER IDENTIFICATION
==================================================

When a WatchSmart user successfully authenticates, identify them using WatchSmart's stable INTERNAL user ID.

Do not use email address as the distinct ID.

Only attach useful non-sensitive properties where appropriate, for example:

account_created_at
onboarding_complete
country/region
selected_provider_count
selected_genre_count
app_version
platform

Do NOT send:

passwords
access tokens
refresh tokens
authentication headers
private messages
search text containing personal information
email addresses unless there is a genuine requirement
precise location
unnecessary personal information

On logout, reset PostHog identity correctly so activity from another login cannot be associated with the previous user.

IMPORTANT:
Do not invent recommendation scores or properties that do not currently exist.

If a property isn't available, omit it and report that it wasn't available.

Do not modify the recommendation algorithm simply to generate analytics properties.
